# 听评快速档（QwenWork 原生听音频路线）

## 定位与选档

- **默认路线**：结论全部来自 QwenWork 内置音频理解对录音的**两遍原生细听**，不出任何声学实测数据。实测主流程（三套本地识别 + 声学实测，约 2.6 GB 模型）只在用户明确要求测量值或详细版两页时才走。
- 代价先讲清（选档时向家长方保密，对自己不保密）：① 录音**上云**处理，隐私敏感案例不选这条；② 云端模型升级后同一录音的听感结论会漂移，不可复现；③ 无词级计时，停顿只能给量级。要详细版两页、要内部依据文件、要可复现证据，回实测版。
- 排版同一脚本、同一 schema：`theme` 六套马卡龙、`teacher`（右栏便利贴，评语 AI 写、署名问老师），规矩都照 `type-system.md`；简版不印全文，录音时长只在页眉。
- 两版产物**不混装**：听评材料零测量值、无「实测 / 声学」字样；实测材料不混听感措辞。量规、花数分档、成长阶段推导两版同一套（`rubric.md`），简版排版同一脚本。听评档**只出简版一页**。

## 第一步：素材与原文（同主流程规矩）

- 案例目录、`case.json`、任务类型 `task = speak | read` 的判定照 SKILL.md 第一步。朗读必须拿原文 `original` 与核心词 `focus`——自动纠正偏置在云端模型上同样存在（mule 读错时照样被听成 meal），只有对着原文才查得出读错的词。
- 视频先抽音轨：`ffmpeg -i input.mp4 -vn -c:a copy audio.m4a`，音频理解吃音轨比吃整段视频稳；照片另抽帧挑选（看镜头、睁眼、表情自然），cover 裁切进简版。
- 拿不到原文时先按录音内容搜教材 / 绘本名（第二遍的锚），但**只认书上原文**；搜不到就明说「原文未逐字核对」，发音结论降一级、不下「系统性失效」这类总量判断——用导读或教学 PPT 拼出来的「原文」会把读对的词判成读错（Tiger 案的教训见文末）。

## 第二步：两遍听协议（核心工作法）

- **第一遍裸听转写**：逐句带时间标；**禁自动纠正**——孩子说错的词用近音拼写记实际听到的音，括注意图词；区分孩子与大人（大人的提醒、插话、跟唱不算孩子的表现，评分时排除，报告不提）；只记英语本身，唱歌表演类不记音准、节拍、音量；标长停顿、重说、填充词（原生听音频能直接听到「嗯、啊」，这点比识别转写可靠）。
- **第二遍原文锚定**：把逐句目标文本与音轨一起送回，逐句核对五件事——① 逐词发音偏差（`focus` 核心词逐个过，再查词尾辅音、常混元音对，定位到元音或词尾；每处记成「目标音 → 听到的音 + 例词」，供 SKILL.md「纠音」挑一个写进 `focus_sound`）；② 流利度（停顿位置与归因：找词停顿多在内容词前；填充词与重说计数，零也要明记）；③ 语调（逐句句尾调型、重音落点）；④ 与原文差异（朗读查漏读 / 添读 / 换词，自创开场收尾算「自己的话」）；⑤ 可懂度（语境能懂 vs 单听会岔）。
- **防自动纠正三纪律**：原文在手逐词对照，专盯「说的和写的不一样」；同段换提示听两遍；发音结论只写「听到的是 Y」。

## 证据等级与措辞（红线）

- **零测量值**：秒数、语速、半音、次数不进任何家长材料——没有声学实测支撑的数字就是编造。停顿写「几处一秒上下的停顿」量级，不给精确秒。
- 听感只写「**像 X**」粒度，不写精确音标：两遍对同一个词可能给出不同听感（实测教训：mule 一遍像 meal、一遍像 mull），结论级一致就保留结论、丢弃听感分歧。
- 填充词措辞用听感口径「没有听到 um、啊」，不写声学口径的「无填充词」。
- 方法注 / 页脚不得出现「声音直接测量录音本身」类实测表述；`claims.md` 的「原生音频声学分析」卖点**不适用**听评产物，宣传材料引用前先核对口径。
- 能力边界（对内心里有数，不对家长展开）：云端依赖、不可离线、结论随模型版本漂移、无词级计时。

## 评分与排版

- 六维按 `rubric.md` 照常定档。声音三维**没有 `score_sound.py` 兜底**，是听评判断——每朵花必须配一句听感证据，3 朵及以下要具体到词；发音档证据是「听感对照」级，措辞相应降级。
- 排版同 `scripts/build_simple.py` + `case.json`（schema 与实测版完全一致，dims / goal / games / mark 由两遍听结果填写）。底部那座山要孩子自己的包络：`case.json` 写 `audio`（音轨或视频路径）即可，`build_simple.py` 缺 `audio_data.json` 时会在本机用 ffmpeg + numpy 自动取 50 ms 响度包络（只画形状、页眉算时长，不上云、不印任何测量值，与「听评材料零测量值」不冲突）；也可以手动跑 `python3 scripts/extract_audio_data.py 音频或视频`。连录音文件都不在手时，山退成一道平缓的坡、不画声波、也不长植物——听评版天然无假波形。
- 页面内容宁精勿满：放不下时先精简解读 / 游戏 / 老师评语，不缩字号、不删结论。渲图目检照主流程清单逐项过。

## 验收追加（听评档）

- 家长材料零测量值、无实测字样、无音标级断言。
- 全文与第二遍核对稿一致，不添不减；每个结论可回指一句原话或一次听感。
- 花数 / 印章 / 评语 / 雷达四处一致；`mark` 词三处对齐（全文、发音解读或小目标）。
- 参照案例与教训：Apple《The Tiger by the Lake》（2026-11-10，read 任务，108 秒视频）。听评档两遍听曾判 magic e 系统性失效（lake 像 lack、mule 像 mull、cage 像 cadge），发音 3 朵；其后同一条录音走实测复核，三套识别只坐实 mule（三次都被听成 meal）与 stone（2:1 被听成 storm），发音 4 朵，另检出一声「嗯」。原因：当时第二遍锚定的「原文」是从教学 PPT 拼的，不是书上逐字原文——**锚错了，读对的词也会被判成读错**。硬规矩：原文必须是书上原文；拿不到就明说「原文未逐字核对」，别下「系统性失效」这种总量判断。
- 写法同 `SKILL.md`「怎么写：阶段能力，不是录音复述」：凭这一次表现推断现阶段能力，用肯定句写，再用两遍听到的现象作证据；听评档的证据用听感措辞（「读成」「听起来」），不出测量值；录音没触及的能力不写也不提。
